Hit System

Area attacks as shapes: a circle, a directional rect or a sector. The chunk index hands over only the entities near the shape; groups and height bands decide who can be hit; an optional order decides who is hit first and where a shield stops it.

Overview

Every hit runs the same four steps

Who can hit whom

Two bit spaces that never mix

Entity groups (on the chunk side) say what an entity is: GROUND, AIR. Targeting searches for them. Hit groups (on the hit side) say what an entity's hits carry and what it can be hurt by. They are a separate 64-bit space, so "can be targeted" and "can be hurt" are independent: an archer can target a flying wraith and hurt it, a swordsman can neither.

Step 1

Gather: only entities near the shape, each once

_gather_chunk_candidates() receives the chunk area under the shape's bounding box. For every column in it, it first asks _column_has_opponent(): does any other team have a membership count above 0 here? If not, the whole column is skipped. Inside an open column the same question is asked per chunk. Only then is the chunk's slot chain walked.

A large entity stands in several chunks, so the same id can show up several times. A visit stamp makes the dedup one integer compare: every gather raises _visitStamp, and an entity whose _entityVisitStamp already equals it was seen in this gather. Every new id then passes _can_be_hit(), which checks everything that does not depend on the shape:

  1. 1

    Team: an entity of the emitter's own team is never hit (and never the emitter itself).

  2. 2

    Removal: announced (_isEntityPendingRemoval) or removed entities are skipped.

  3. 3

    Groups: hitGroups(emitter) & hurtGroups(target) != 0.

  4. 4

    Height: the hit band and the target band overlap.

The third axis

Height bands, sample height and the radius curve

Positions are 2D. Height lives in bands: every entity has a height band (bottom, top) and every hit has one too. The bands must overlap for the hit to count. The hit is then measured at one sample height: the middle of the hit band, clamped into the target's band. At that height the target offers its effective radius: its radius times the radius curve's factor at that height, or the plain radius without a curve.

# _get_effective_radius(id 2, sample height 144) band = (96, 160), height 64 cursor = clamp((144 − 96) / 64, 0, 1) * 64 = 48.0 # position among the 65 samples lower = min(int(48.0), 63) = 48 factor = f[48] + (f[49] − f[48]) * 0.0 = 0.8125 # linear between two baked samples radius = 40 * 0.8125 = 32.5

The curve is baked once per Curve resource into 65 factors (_curveRadiusFactors); a hit reads two floats and never calls into the Curve object. An entity whose band has zero height keeps its plain radius.

Step 2

Three shapes, each with its own order

A target is accepted when its silhouette (a circle of the effective radius) reaches into the shape. Each accepted target gets a sort key (lower lands first in an ordered hit) and an impact: the point on its silhouette facing the hit's origin, with the sample height as third coordinate.

Circle · hit_circle(…, p_isOrdered)

Test: distance(target, origin) ≤ radius + targetRadius.

Order: p_isOrdered = true lands targets from the center outwards; the sort key is the squared distance.

Bounds: the square origin ± radius.

Directional rect · hit_directional_rect(…, p_order)

Frame: origin is the center of the back edge; the rect extends length along direction and width across it. along and across are the target's coordinates in that frame (across is positive to the right of the direction).

Test: the distance from the target center to the rect is at most the target radius: gapAlong² + gapAcross² ≤ r², where a gap is how far the coordinate lies outside the rect's range.

Bounds: the axis aligned box around the four corners.

Sector · hit_sector(…, p_order)

Frame: a cake slice with its tip at origin, centered on direction, reach radius, full openingAngle in radians.

Test: first distance ≤ radius + r. Then, if the target center lies within half the opening angle, it is in. If not, its circle may still touch one of the two straight edges: _touches_sector() takes the closest point on each edge segment and checks it against r.

Order: the signed angle against the direction. LEFT_TO_RIGHT sorts by it, RIGHT_TO_LEFT by its negation: a sweep across the slice.

Step 3

Dispatch: order, cut, snapshot, hand over

  1. 1

    Limit. maxHits caps the number of targets; UNLIMITED_HITS (−1) means all accepted.

  2. 2

    Choose. Unordered: the first limit accepted targets in gather order. Ordered with limit 1: the lowest sort key, found in one pass. Ordered otherwise: insertion sort by key (_acceptedOrder), then walk it; the first target whose hurt groups meet the emitter's stop groups is still chosen, and ends the list.

  3. 3

    Snapshot. The chosen ids and impacts are copied into local arrays. A module manager may fire a hit of its own while it takes one (thorns, a death explosion); that reuses the server's buffers, but the running dispatch only reads its snapshot.

  4. 4

    Hand over. For each chosen target: skip it if a module manager announced or removed it meanwhile; otherwise record its impact and call module_manager.hit(hitData) (a null manager is skipped silently). Returns the impacts of the targets that really landed, in landing order.

Step 0

Preferred target: test one entity before any chunk

A single target attack usually knows whom it is aimed at. Passing that id as p_preferredTargetId with p_maxHits = 1 tests that one entity first: _can_be_hit(), then the shape. If it lands, the hit is done without touching a single chunk. If it cannot be hit or misses the shape, the normal gather runs as if no preference was given. With any other maxHits the preference is ignored, and a warning is printed once.

G_HitServer.hit_sector(3, Vector2(420, 300), Vector2(-164, -172), 300.0, PI / 3.0, Vector2(96, 192), 1, 2, arrowData, C_HitServer.SECTOR_ORDER.NONE) # id 2: team ✓, not removed ✓, RANGED & RANGED ✓, band (96, 192) vs (96, 160) ✓ → only candidate # distance 237.7 ≤ 300 + 32.5, angle 0° ≤ 30° → accepted → lands → returns [(278.4, 151.5, 144)]

Reference · instance vars of G_HitServer

Scratch data

State of the hit that is running, kept on the G_HitServer instance and reused by every hit, so no hit allocates buffers. Values are shown right after the worked example's resolve step. The buffers are only valid up to their count; cells beyond it hold leftovers of earlier hits.

VariableTypeHolds
BUFFER_MIN_CAPACITYint (cached)Smallest size a reused buffer grows to

Cached C_HitServer.BUFFER_MIN_CAPACITY = 16. A full buffer grows to max(count * 2, 16): the first candidate grows it from 0 to 16, the 17th to 32, and so on. After a few hits the buffers never grow again.

UNLIMITED_HITSint (cached)−1: no hit limit

Cached C_HitServer.UNLIMITED_HITS. Passed as p_maxHits it lets the hit land on every accepted target (still cut by stop groups in an ordered hit).

_candidateIdsPackedInt32ArrayEntities near the shape that passed the checks

Filled by the gather (or the preferred check), valid up to _candidateCount. Each entry passed team, removal, group and band checks; only the geometry is left.

_candidateCountintHow many candidate entries are valid

Reset to 0 at the start of every gather and of the preferred check. Resetting the count instead of clearing the array is what makes the buffer reusable at no cost.

_acceptedIdsPackedInt32ArrayTargets whose silhouette reaches the shape

Written by _accept_target() during the resolve step, parallel to _acceptedSortKeys and _acceptedImpacts: index i of all three belongs to one target.

_acceptedSortKeysPackedFloat32ArrayLanding key per accepted target; lower first

Circle: squared distance. Rect: along, length − along, across or −across. Sector: ± signed angle. Only read by an ordered hit.

_acceptedImpactsPackedVector3ArrayWhere the hit meets each silhouette

(x, y, height): the point on the target's circle of effective radius that faces the hit origin, at the sample height. What hit_*() returns, for effects and sounds.

_acceptedCountintHow many accepted entries are valid

Reset to 0 by every _resolve_*_hit() before it tests candidates.

_acceptedOrderPackedInt32ArrayAccepted indices sorted by key

Filled by _sort_accepted_by_key() (insertion sort) for ordered hits with a limit above 1. Holds indices into the accepted buffers, not entity ids.

_visitStampintNumber of the running gather

Raised by one before every gather. Because it only grows, a stamp from any earlier gather can never equal it, so nothing has to be cleared between hits.

_entityVisitStampPackedInt32ArrayThe gather that last saw each entity

Per entity id. When a slot walk meets an entity whose stamp equals _visitStamp, it was already collected in this gather and is skipped. Grown to the entity count at the start of a gather. Scratch data, so it lives on G_HitServer, not on A_CoreServer.

_hasWarnedPreferredMisuseboolThe preferred target warning was printed

Set the first time a preferred target comes with p_maxHits other than 1, so the warning appears once instead of every tick.

G_HitServer.hit_circle(3, pos, 90.0, band, 5, 2, data, false) # WARNING: G_HitServer: a preferred target is only used when p_maxHits is 1, ignoring it. (once)

Contract

What the caller has to respect

  • Use the returned impacts, not the scratch buffers. The buffers belong to whichever hit runs next.
  • A preferred target needs p_maxHits = 1. Otherwise it is ignored with a one-time warning.
  • Stop groups only act in ordered hits. Pass p_isOrdered = true or an order other than NONE.
  • Hit groups and entity groups are separate spaces. Being targetable says nothing about being hurtable.
  • A radius curve needs max_value > 0. Any domain works; it is mapped onto the entity's height band.
  • Module managers may re-enter. Firing a hit or removing an entity inside hit() is safe; a target removed that way is skipped.
