Architecture

Four levels, one rule

Every entity stands in one or more chunks, depending on its radius. A fixed number of chunks forms a row, all rows form the map. Each of those three levels carries the same two aggregates per team: a bitmask of the groups present, and a plain entity count.

The rule that keeps it cheap: counts are always written through, masks only cascade upwards while they actually change. A removal can therefore never force a rescan of the whole map — it stops at the first level whose mask comes out unchanged.

Entities are pure data. There are no nodes and no objects per entity: an entity is an integer id, and every property is one slot in a packed array at that index. Ids are recycled, but never within the frame they were released in.

What changed against the original spec

Counts

Counts live in one place, not in the rebuild functions. The spec had _rebuild_row_groups and _rebuild_map_groups decrement the row and map counts, but those only run when a mask changed — the counts would drift apart whenever the cascade stopped early. _apply_count_delta() now writes chunk, row and map counts on every add and remove, exactly as the spec's own third decision requires.

Layout

One flat array per kind of data, with a block per team, instead of an …Attacker / …Defender pair. Every function already takes a team, so indexing by it removes the branch from every access — see memory layout.

Fast path

Movement that stays inside the same chunks costs almost nothing. Each entity caches the chunk rectangle it covers, so set_position() can drop out after one comparison — see fast path.

Rebuilds

The three rebuilds stop as soon as the answer is decided. They are only reachable from the remove path, where a mask can only shrink, so once the running OR reaches the old value the rest of the scan cannot change it.

Added

set_radius() joins the public API. It shares the delta logic with set_position() through _apply_chunk_area(), so a resize updates the same chunks a move would.

Aggregation

Add cascades by OR, remove cascades by rebuild

A bitmask grows for free: mask |= groups. It cannot shrink the same way — clearing a bit would be wrong as long as any other entity still holds it. So the two directions are genuinely different operations, and only the add path is O(1) per level.

Data

Structure of arrays, one block per team

There is no entity object and no per-team container. Each kind of data is a single packed array; the team selects a block inside it and the chunk or row selects the slot:

team 0 · attackerindex 0 … CHUNK_COUNT-1
team 1 · defenderindex CHUNK_COUNT … 2·CHUNK_COUNT-1
## Maps team and chunk onto the slot inside the per team chunk containers. func _get_team_chunk_index(p_team: int, p_chunkId: int) -> int: return p_team * C_ChunkingServer.CHUNK_COUNT + p_chunkId

Movement

The rectangle check that skips the work

Both set_position() and set_radius() go through _apply_chunk_area(). It compares the new rectangle against the one the entity already covers, and returns before touching a single chunk when they match — which is what happens on the large majority of movement calls.

How to use

Wiring it into a scene

The server is a plain RefCounted, not an autoload — the system that owns the entities owns the server, and the grid comes from C_ChunkingServer at class load. Create it, register entities, push positions, and close each frame.

## Owns the units of one battle and keeps their chunk assignment current. extends Node class_name Battlefield ## Group bits every unit type is matched against. const GROUP_INFANTRY: int = 1 << 0 const GROUP_ARMOR: int = 1 << 1 const GROUP_AIR: int = 1 << 2 ## Spatial index of every living unit. var _chunking: ChunkingServer = ChunkingServer.new() ## Ids of the units this battlefield drives. var _unitIds: PackedInt32Array = PackedInt32Array() ## Registers one unit and keeps its id. ## @param p_position Where the unit spawns ## @return The registered entity id func spawn_infantry(p_position: Vector2) -> int: var l_id: int = _chunking.register_entity( p_position, 48.0, C_ChunkingServer.TEAM.ATTACKER, GROUP_INFANTRY, GROUP_ARMOR | GROUP_AIR, null) _unitIds.append(l_id) return l_id ## Pushes the new positions and closes the frame for the chunking server. ## @param p_delta Time since the last physics step func _physics_process(p_delta: float) -> void: for l_id: int in _unitIds: _chunking.set_position(l_id, _get_movement_target(l_id, p_delta)) _chunking.release_removed_ids()

Per frame order

  1. 1

    Move whatever moved — set_position() and set_radius() may be called in any order and as often as needed.

  2. 2

    Run the systems that read the index: targeting, auras, spatial queries. Every mask and count is already correct, there is no rebuild step to trigger.

  3. 3

    Announce deaths with pre_unregister_entity() while other systems may still need the entity, then remove them with unregister_entity().

  4. 4

    Call release_removed_ids() once, last. Only now do removed ids become available to register_entity() again.

Asking spatial questions

## Cheap to expensive: the map mask rules out a whole search before it starts. func find_air_threats(p_position: Vector2) -> PackedInt32Array: if (not _chunking.map_has_group(C_ChunkingServer.TEAM.DEFENDER, GROUP_AIR)): return PackedInt32Array() return _chunking.get_entities_in_radius(p_position, 320.0)

The three has_group queries exist to be asked first. A map check is one AND and rules out every chunk at once; a row check narrows to one band; a chunk check tells you whether iterating its entity list is worth it at all.

Reference

Public API

Eleven functions. Everything else is _-prefixed and internal to the cascade. p_team is always a C_ChunkingServer.TEAM value, p_groups and p_groupMask are always 64-bit bitmasks.

Commands

register_entitypublicO(covered chunks)
func register_entity(p_position: Vector2, p_radius: float, p_team: int, p_groups: int, p_targetedGroups: int, p_module: M_ModuleManager) -> int

Takes an id from the free list or appends a new slot to every entity container, stores the entity data, and adds it to each chunk its radius covers. Returns the entity id, which is the handle for every other call.

set_positionpublicO(1) unchanged
func set_position(p_id: int, p_position: Vector2) -> void

Stores the position and updates the chunk assignment only if the covered rectangle changed. Safe to call every frame for every entity — that is what it is built for.

set_radiuspublicO(1) unchanged
func set_radius(p_id: int, p_radius: float) -> void

Same delta path as set_position(), for an aura that grows, a shield that expands or a weapon range that changes with a buff. Setting the radius it already has costs nothing.

pre_unregister_entitypublicO(1)
func pre_unregister_entity(p_id: int) -> void

Marks the entity as doomed and changes nothing else — it stays in its chunks, in every mask and in every count. Announcement only, so other systems can stop picking it as a target before it disappears.

unregister_entitypublicO(covered chunks)
func unregister_entity(p_id: int) -> void

Removes the entity from every chunk immediately and runs the full remove cascade. The id goes to the pending list, not the free list: it stays locked for the rest of the frame so a queued reference cannot silently resolve to a different entity.

release_removed_idspublicO(removed since last call)
func release_removed_ids() -> void

Moves the pending ids into the free list, clears their flags and drops their module reference. Call it once per frame, after every other system that could still hold a removed id has run. Skip it and ids are never recycled; call it mid-frame and an id can be handed out while something still references it.

Queries

chunk_has_group · row_has_group · map_has_grouppublicO(1)
func chunk_has_group(p_chunkId: int, p_team: int, p_groupMask: int) -> bool func row_has_group(p_rowIndex: int, p_team: int, p_groupMask: int) -> bool func map_has_group(p_team: int, p_groupMask: int) -> bool

One bitwise AND each. Always correct with no lazy rebuild, because the cascade keeps all three levels current. Use them as the filter in front of any iteration.

get_entities_in_chunkpublicO(1)
func get_entities_in_chunk(p_chunkId: int) -> PackedInt32Array

Returns the chunk's own list, not a copy. Treat it as read only — and do not hold it across a call that adds or removes an entity in that chunk, because swap-and-pop reorders it.

get_entities_in_radiuspublicO(entities in covered chunks)
func get_entities_in_radius(p_position: Vector2, p_radius: float) -> PackedInt32Array

Collects the candidates from every covered chunk, then filters by true squared distance. Each id appears once: an entity standing in several of the covered chunks is only checked against the result list when it actually spans more than one.

Filters by point in circle, using the entity position against the query radius — the entity's own radius is not added. For circle-overlap semantics, query with p_radius + maxEntityRadius and re-filter.

Square chunks, whatever you configure

A column count and a row count imply two different chunk edges. If they disagree, the chunks are rectangles. The recalculation takes the edge closest to both wishes, uses it on both axes, and derives the counts back from it so the grid still covers the whole map:

l_columnEdge = CONFIGURED_MAP_SIZE.x / CONFIGURED_CHUNK_COLUMNS l_rowEdge = CONFIGURED_MAP_SIZE.y / CONFIGURED_CHUNK_ROWS CHUNK_SIZE = (l_columnEdge + l_rowEdge) * 0.5 MAP_CHUNK_COLUMNS = ceil(CONFIGURED_MAP_SIZE.x / CHUNK_SIZE) MAP_CHUNK_ROWS = ceil(CONFIGURED_MAP_SIZE.y / CHUNK_SIZE) MAP_SIZE = Vector2(MAP_CHUNK_COLUMNS, MAP_CHUNK_ROWS) * CHUNK_SIZE

Already-square configurations pass through untouched — the first row is the shipped default. Otherwise the grid may end slightly larger than configured, never smaller, so no position falls outside it. Positions beyond MAP_SIZE clamp into the border chunks rather than erroring.

Contract

What the caller has to respect

  • release_removed_ids() once per frame, last. It is the only thing that recycles ids, and the lock it releases is what makes a queued damage event safe.
  • An unregistered id is dead until re-registered. Do not move it, resize it or query with it — the server does not re-check a caller's id.
  • 64 groups maximum. Groups are bits in an int64. Group values are the caller's to define; the server only ORs and ANDs them.
  • Teams are array indices. Pass TEAM values, not arbitrary integers; a third team needs only a new enum entry.
  • get_entities_in_chunk() hands out live state. Read it, do not store it, do not write to it.
  • The grid is fixed after class load. Changing the configuration means changing the constants and restarting — there is no resize.

Correctness

The same transliteration is fuzz-tested against a brute-force rebuild: 50 trials × 500 random operations mixing registration, long moves, sub-chunk nudges, radius changes, removal and frame ends. After each batch every chunk mask, every count at all three levels, the entity-to-slot index mapping, the cached rectangle and the id lifecycle are compared against a full recomputation. All pass.

That validates the algorithm, not the GDScript. The scripts have not been through the Godot parser yet, so the first editor run is still the real smoke test.
