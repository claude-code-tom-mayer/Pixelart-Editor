Overview

Why this server exists

GDScript has single inheritance. If the hit server and the targeting server each extended the chunk index, each would carry its own index and its own id space — entity 7 in one would be a different entity from 7 in the other, every position would have to be pushed twice, and no id could be passed between systems.

The api server fixes that by being the index. It extends ChunkingServer, so it holds the chunks and the shared entity slots itself, and it constructs the other servers with a reference back to itself. There is exactly one index, one id space, and one place an entity talks to.

Architecture

One index, servers beside it

Ownership

Each server holds only what it uses. Module references live in the hit server because only it dispatches; targeted groups live in the targeting server because only it searches. The index keeps what it needs to place things in space and nothing else.

Access

Shared slots are public, bookkeeping is private. entityPosition, entityTeam, chunkCounts and the rest are read directly by the servers on top. The cascade internals — _chunkGroups, _entityChunkIndices, the free list — stay private to the index.

Cost

No accessor calls in any hot loop. A search or a hit reads _chunking.entityPosition[id] — a property lookup plus an array index. Going through getters would have put a GDScript function call on every candidate, which is the most expensive thing in the language.

Lifecycle

One call, split three ways

An entity is described once, by an R_EntityData that an archetype can share. The api server takes it apart and gives each server exactly its own part — no server ever sees another's setup.

## Everything one archetype of entity needs to exist, across all servers. class_name R_EntityData @export var radius: float # -> chunk index @export var groups: int # -> chunk index @export var hitProfile: R_HitProfile # -> hit server @export var targetingData: R_TargetingData # -> targeting server
  1. 1

    create_entity() calls the inherited register_entity(), which takes an id and places the entity in every chunk its radius covers.

  2. 2

    That same id goes to HitServer.register() with the module manager and the hit profile, and to TargetingServer.register() with the targeting data. Each grows or resets its own slot.

  3. 3

    pre_unregister_entity() marks the entity and tells the targeting server, so everyone aiming at it starts looking elsewhere while it is still alive.

  4. 4

    unregister_entity() unlinks it from the targeting graph, then removes it from every chunk. Its id is locked, not free.

  5. 5

    release_removed_ids() lets the hit server drop the module reference and the radius curve slot, then hands the ids back for reuse.

A recycled id can never inherit anything: the index overwrites its slots on registration, and both servers reset theirs in _ensure_slot() before writing the new setup.

How to use

A round, from spawn to frame end

## Drives one battle through the single entry point. extends Node class_name Battlefield ## The one server every entity of this battle talks to. var _api: ApiServer = ApiServer.new() ## Ids of the units currently alive. var _unitIds: PackedInt32Array = PackedInt32Array() ## Spawns one unit of an archetype. ## @param p_position Where it spawns ## @param p_team Which side it fights for ## @param p_entityData The archetype to build it from ## @return The registered entity id func spawn(p_position: Vector2, p_team: int, p_entityData: R_EntityData) -> int: var l_id: int = _api.create_entity(p_position, p_team, M_ModuleManager.new(), p_entityData) _unitIds.append(l_id) return l_id ## Runs one tick of the battle. ## @param p_delta Time since the last physics step func _physics_process(p_delta: float) -> void: for l_id: int in _unitIds: var l_state: int = _api.update_entity(l_id) if (l_state == C_TargetingServer.STATE.SEARCH): _api.search_target(l_id) _api.set_position(l_id, _step_towards(l_id, _api.get_target_position(l_id), p_delta)) _api.release_removed_ids()

The entity never touches a sub-server. Searching is triggered by the entity itself, so the work can later be spread across ticks without changing anything here.

Contract

What the caller has to respect

  • Entities talk to the api server only. The sub-servers are private on purpose — reaching past the facade is how two id spaces come back.
  • Everything is set at registration. The setters exist for changes during a round, not for building an entity in pieces.
  • An R_EntityData is an archetype. Share one per unit type; the servers copy the values into their own arrays, so nothing is aliased.
  • release_removed_ids() once per frame, last. It is the only thing that recycles ids, and it is where the hit server drops module references.
  • Public slots on the index are read only for everyone but the index. Writing entityPosition directly skips the chunk update and corrupts the grid — use set_position().
