Architecture

One base class, three autoloads, one storage

A_CoreServers is not an autoload itself — it is an abstract Node subclass. G_ChunkingServer, G_HitServer and G_TargetingServer each extends A_CoreServers and are the three autoloads the rest of the game actually calls. Every per-entity field chunking, hit and targeting need — _chunkEntityTeam, _hitEntityYBand, _targetingEntityTarget, and everything else — is declared once on A_CoreServers as static var.

Godot 4.3+ GDScript shares a static var across every subclass that does not redeclare it. So although there are three separate autoload instances, there is exactly one copy of each array in memory, and any of the three can read or write an entity's chunking, hit or targeting data directly — no cross-autoload call, no signal, no lookup. G_HitServer reading _chunkEntityPosition[id] to resolve a hit is not a layering violation; it is the point of the design.

What is not static is the handful of cached scalar constants (MAP_CHUNK_COLUMNS, TEAM_COUNT, NO_ID, and so on) declared as plain var in Constants below. Each of the three autoload instances gets its own copy, filled in by _init() once when that instance is created — cheap enough that it not being shared costs nothing, and simple enough not to need the static machinery.

This page documents what lives on A_CoreServers and C_CoreServers only. The data each domain owns and the queries built on top of it are documented on their own pages — Chunking, Hit, Targeting — which link back here for anything shared.

Entity ids

One id, four calls, three domains filled in at once

An entity is never an object — it is an integer id, handed out by register() and reused once release_removed_ids() frees it. Before A_CoreServers existed, chunking, hit and targeting each ran their own id lifecycle and their own free list; an entity that should not take hits still needed a hit-side registration call with empty groups, just to keep the three id spaces in step. Now there is exactly one id space, and one call sets up all three sides.

  1. 1

    register() takes a free id or appends a fresh slot to every array on all three domains, then fills in the chunking side (team, groups, position, radius, chunk membership), the hit side (falling back to a shared default profile when none is given) and the targeting side (falling back to plain zeroed defaults). A null hit profile or targeting data makes the entity inert on that side, not unregistered from it.

  2. 2

    pre_unregister() marks the id without removing it from anything: it stays fully active and hittable in the grid, but every entity currently targeting it is dropped and told to search again. Typical use is a death animation — the entity should still take up space and keep moving for a moment, but nothing should waste an attack on it.

  3. 3

    unregister() drops its own target, drops every one of its own targeters, unlinks it from every chunk it covers and from the center chain, and appends the id to the pending-free list. The id is locked from here on — it will not be handed out again yet.

  4. 4

    release_removed_ids() is called once per frame, after everything that could still reference a removed id has run. It resets every field of every pending id back to default, moves the id onto the reusable free list, and emits s_entityReleased.

The lock between steps 3 and 4 matters: if an id were reusable the instant unregister() ran, a queued hit resolving later in the same frame could land on a brand-new entity that happens to have been handed the same id. _chunkEntityUnregistering keeps the old id skipped by every query until the frame's cleanup pass runs. The full timeline, drawn with the flag values at each phase, is on the Chunking page.

C_CoreServers

A small file on purpose. Chunking, hit and targeting each used to define their own −1 "points nowhere" constant — C_ChunkingServer.NO_SLOT, NO_ENTITY and NO_COLUMN, C_TargetingServer.NO_TARGET, C_HitServer.NO_CURVE — five names for the same value, because each domain only ever compared it against its own arrays. C_CoreServers.NO_ID replaces all five.

NameKindMeaning
NO_IDconst int−1, wherever a slot, chunk, center link, target or curve points nowhere

Cached onto every autoload instance as NO_ID in A_CoreServers._init(), the same way MAP_CHUNK_COLUMNS and the other shared constants are. Used across every domain:

  • Chunking — end of a coverage chain (_chunkHead, _chunkEntitySlotHead), end of a center chain (_centerHead), a team's occupied column span when it holds nothing (_teamMinColumn/_teamMaxColumn), and an entity's center chunk before its first placement.
  • Hit — the curve slot of an entity whose radius is constant over its height (_hitEntityCurveIndex).
  • Targeting — the target of an entity that has none (_targetingEntityTarget), and the running search's best-candidate ids before anything has been scored.

One value, one name, everywhere it is compared — a search that used to need to know whether it was comparing a slot, a center link or a target now just compares against NO_ID.
