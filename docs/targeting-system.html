Targeting System

Picks a target per entity, keeps it until something takes it away, and says where the entity should move. Searches walk the chunk grid ring by ring, count distance in chunks, and score candidates with a handful of integer tests.

Idea

A target is lost, never re-checked

Once acquire_target() picked a target, nothing ever asks "is it still the best one?". The target stays until one of a few events takes it away, and each event knows exactly whom to tell, through the targeter chain (everyone targeting an entity, stored on the target). That makes the per tick work tiny: update_state() only compares a distance and walks the entity's own targeters.

update_state()

Four states, decided in one cheap call

update_state(id) runs every tick and never searches:

  1. 1

    If the entity is away from its base (more than BASE_REACHED_EPSILON along x) and threatened (a targeter within its flee radius): drop the target, state FLEE.

  2. 2

    Else no target: SEARCH.

  3. 3

    Else target within combatRange + target radius: COMBAT.

  4. 4

    Else APPROACH.

Marching is not a state: an entity in SEARCH without anything to find simply moves where get_move_destination() sends it.

acquire_target()

One ring walk, two winners, each entity seen once

acquire_target(id) ignores a removed id with a warning, then calls _find_best_target() and, if it found one, _assign_target(). The search:

  1. 1

    Map filter. Searched groups = targeted | priority. If no other team's _teamMapGroups shares a bit with them, return NO_ID without touching a chunk.

  2. 2

    Rings. For ring 0 (the searcher's center chunk), 1, 2 … up to the search radius: stop if the search is settled, else scan the ring.

  3. 3

    Column filter. A ring is walked column by column; a column whose opponent column mask has no searched group is skipped with all its chunks. The ring's two outer columns contribute every row of the ring, inner columns only its top and bottom row.

  4. 4

    Chunk filter, then centers. A chunk whose opponent chunk mask has no searched group is skipped; otherwise its center chain is walked, so every entity is met exactly once.

  5. 5

    Candidate check. Other team; not announced or removed; has a searched group; visible, or the searcher can see invisible.

  6. 6

    Two winners. A candidate with a priority group competes for _bestPriorityId, any other for _bestNormalId. Higher score wins; a tie goes to the lower id, so the result never depends on storage order. At the end any priority winner beats the normal one.

_score_candidate()

Five terms, no geometry

TermValueWeight (C_TargetingServer)Reason
ClosenesssearchRadius − chunkDistanceWEIGHT_CLOSENESS = 1.0nearer is better; at the search edge it is 0, beyond it negative

Worked example: archer id 3 searches

Id 3 (column 3, row 2, forward +1, search radius 6, targets GROUND | AIR, priority AIR, can see invisible) searches in the example world before it has a target. The map filter passes (defenders hold 0b11). Ring 0 is chunk 11: the defender column 3 mask is 0, skipped. Ring 1 opens column 2 and walks chunk 6's center chain: id 2, then id 1. Nothing else in rings 2 to 6 has a defender center.

Chunk distance

Distance between center chunks, not positions: diagonal = min(|Δcolumn|, |Δrow|), straight = max(…) − diagonal, distance = straight + diagonal * DIAGONAL_CHUNK_COST (1.45, close to √2 without a square root). It is used for the closeness score and for the flee radius.

_is_search_settled()

Stop as soon as no further ring can win

Every chunk of ring r is at least r steps away, so no candidate there can have closeness above (radius − r) * WEIGHT_CLOSENESS. Add the largest bonus any candidate could get (BEHIND + MUTUAL, plus FOCUS unless the searcher ignores focus; crowding only subtracts) and you have the best score still reachable. Before scanning ring r:

  • a priority winner exists → stop if its score ≥ the reachable bound;
  • no priority winner, but the map holds priority groups → never stop early: a priority candidate beats any score;
  • otherwise → stop if the normal winner's score ≥ the bound.

In id 3's example the priority winner (7.55) stays below every bound (13 at ring 6), so that search runs to the end; in the 4 × 3 example world that end is reached quickly because most rings lie off the map.

_is_threatened() · _is_away_from_base()

Fleeing: a targeter too close, far from home

An entity is threatened when any entity in its targeter chain has a center chunk within its flee radius (chunk distance ≤ fleeRadiusChunks); NEVER_FLEE skips the walk. It only flees while away from its base: more than BASE_REACHED_EPSILON (32 units) from its team's base x. Fleeing drops its own target at once; the entity then heads for its base.

_assign_target() · _clear_target() · _release_targeters()

The link that goes both ways

_entityTarget points from the targeter to its target. The targeter chain points back: _entityFirstTargeter[target] is the head, _entityTargeterNext/Prev are stored in the targeters' own cells (each entity has at most one target, so it sits in at most one chain). _assign_target() first clears the old target, then pushes the targeter at the head and raises the count.

Invisibility releases only those who cannot see

G_TargetingServer.set_is_invisible(2, true) # id 2 is invisible from registration; calling it again shows the rule # _release_targeters(2, FLAG_CAN_TARGET_INVISIBLE): walk the chain of id 2 → id 3 # id 3 has CAN_TARGET_INVISIBLE → keeps its target. Every other targeter would drop it. G_TargetingServer.set_is_invisible(1, true) # chain of id 1 → id 0 (flags 0) → _clear_target(0): id 0 back to SEARCH, and a new search cannot find id 1

Scratch data of the running search

_find_best_target() copies what the ring scan needs about the searcher into these vars once, so the inner loops read one instance var instead of indexing shared arrays by the searcher's id again and again. They hold the state of the worked example after ring 1.

VariableTypeHolds
_searcherIdintThe entity that searches

Used for the mutual term: a candidate whose _entityTarget equals it already fights the searcher.

_searcherTeamintTeam of the searcher

Candidates of this team are skipped; the column and chunk filters look at every other team's masks.

_searcherColumn · _searcherRowintCenter chunk of the searcher

The middle of every ring, and the point chunk distances are measured from.

_searcherFlagsintFlags of the searcher

Read for CAN_TARGET_INVISIBLE (may it score invisible candidates?) and IS_IGNORING_FOCUS (does the focus bonus count, and does it enter the settle bound?).

_searcherForwardSignint+1 or −1: which way is forward

A candidate is behind when (candidateColumn − searcherColumn) * sign < 0.

_searchRadiusChunksintRings of the running search

The number of rings beyond ring 0, and the base of the closeness term and of the settle bound.

_searchedGroupsintEvery group the search accepts

targeted | priority. Used by all three mask filters and the candidate check.

_searchedPriorityGroupsintGroups that make a candidate a priority one

A candidate with groups & this != 0 competes in the priority ranking.

_bestPriorityId · _bestPriorityScoreint · floatLeader of the priority ranking

NO_ID and 0 at the start. Returned if set, whatever the normal leader scored.

_bestNormalId · _bestNormalScoreint · floatLeader of the normal ranking

Contract

What the caller has to respect

  • Call update_state() before reading the state or moving. It is what notices combat range and threats.
  • Searching is the caller's decision. update_state() never searches; call acquire_target() when the state is SEARCH, as often as the budget allows.
  • A target is not re-evaluated. A better candidate walking by does not replace it; only the loss events do.
  • Ranges are chunk counts, combat range is a real distance. Changing CHUNK_SIZE changes how far search and flee radii reach.
  • get_targeters() allocates. It is for tests and tools, not for per tick loops.
